Local agent control

Model Context Protocol

Connect an AI agent to Beacon to configure routes and inspect health and delivery state. The server, schemas, reference, and runtime are embedded and operate without an internet connection.

Install Beacon MCP

Register Beacon's local Streamable HTTP endpoint with the agent you use. Run the matching command once while Beacon is running.

Codex

Add Beacon from a terminal:

codex mcp add beacon --url http://127.0.0.1:2112/mcp

Verify with codex mcp list, or open /mcp inside Codex.

Claude Code

Add Beacon as a local HTTP server:

claude mcp add --transport http beacon http://127.0.0.1:2112/mcp

Verify with claude mcp list, or open /mcp inside Claude Code.

Gemini CLI

Add Beacon from a terminal:

gemini mcp add beacon http://127.0.0.1:2112/mcp --transport http

Verify with gemini mcp list, or run /mcp list.

VS Code

Run MCP: Add Server and choose HTTP, or add this to .vscode/mcp.json:

{
  "servers": {
    "beacon": {
      "type": "http",
      "url": "http://127.0.0.1:2112/mcp"
    }
  }
}

If the agent runs on another device, replace 127.0.0.1 with Beacon's address on your trusted onboard network. Claude.ai and Claude Desktop custom connectors run through Anthropic's cloud and cannot reach this localhost endpoint; use Claude Code for the offline setup.

The MCP endpoint can change live configuration. Keep the admin listener on localhost or a trusted onboard network.

Call examples

These are the params bodies sent with MCP tools/call. Read configuration before making a change.

Read configuration

{"name":"get_config","arguments":{}}

Add a SocketCAN source

{
  "name": "put_source",
  "arguments": {
    "source": {
      "id": "can0",
      "name": "Engine room bus",
      "type": "socketcan",
      "enabled": true,
      "interface": "can0"
    }
  }
}

Add an SSE sink

{
  "name": "put_sink",
  "arguments": {
    "sink": {
      "id": "events",
      "name": "Agent events",
      "type": "http_sse",
      "enabled": true,
      "path": "/events"
    }
  }
}

Add a connector route

{
  "name": "put_connector",
  "arguments": {
    "connector": {
      "id": "navigation",
      "name": "Navigation data",
      "source_id": "can0",
      "sink_id": "events",
      "filters": ["msg.pgn in [127250, 129025, 129026, 129029]"],
      "buffer": {"max_age": "24h"},
      "enabled": true,
      "mode": "semantic"
    }
  }
}

Read health

{"name":"get_health","arguments":{}}

Read one route's delivery metrics

{
  "name": "get_delivery_metrics",
  "arguments": {"connector_id": "navigation"}
}

Inspect one source's PGN traffic

{
  "name": "get_source_metrics",
  "arguments": {"source_id": "can0"}
}

Read one sensor's latest PGN payloads

{
  "name": "get_latest_payloads",
  "arguments": {"source_id": "can0", "sensor_id": "address:12"}
}

Behavior

Writes
Validated, persisted to SQLite, and reconciled against the running graph in the same call.
Tool errors
Invalid ids, types, references, CEL, durations, and in-use deletes return correctable MCP tool errors.
Metrics
Reports pending delivery separately from retained history, plus per-source/sender PGN rates, payload sizes, learned gaps, and decoded value distributions.
Latest payloads
Keeps one exact current decoded payload per bounded sensor/PGN stream; no growing payload history is accumulated.
Network
No cloud service, CDN, remote schema, telemetry endpoint, or internet connection is required.
